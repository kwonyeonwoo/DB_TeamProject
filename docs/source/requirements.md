# 요구사항 명세서

## 1. 회원 관리

### 1-1. 회원 가입

이 명세서에서 회원 테이블의 id는 id 또는 회원 id, login_id는 아이디 또는 회원 아이디로 표현한다.

회원으로 가입하려면 이름, 아이디, 비밀번호, 이메일을 입력해야 한다.

회원은 회원 id로(login_id와 다름을 유의) 식별한다.

회원 아이디와 이메일은 중복될 수 없다. 단, 탈퇴한 회원의 경우 해당 두 속성이 null값을 가질 수 있으며, 이 경우에 한하여 중복 가능하다.

### 1-2. 로그인 및 계정 찾기

회원은 아이디와 비밀번호를 입력하여 로그인할 수 있다.

로그아웃 시 서버에 저장된 사용자의 세션을 무효화한다.

세션 무효화 이후 해당 세션으로는 인증이 필요한 기능을 사용할 수 없다.

로그아웃이 완료되면 로그인 페이지로 이동한다.

로그아웃 상태에서 사이트에 접속하면 기본적으로 로그인 페이지로 이동한다.

회원은 본인확인 정보를 이용하여 자신의 아이디를 찾을 수 있다.

회원은 아이디와 본인확인 정보를 이용하여 비밀번호를 찾을 수 있다.

본인확인 정보는 이메일로 한다.

비밀번호 찾기에 성공하면 비밀번호 재설정 화면으로 이동한다.

### 1-3. 회원 정보 수정

회원은 이름, 비밀번호, 이메일을 수정할 수 있다.

회원 정보를 수정할 때 기존 정보와 동일한 내용으로 수정할 수 없다.

### 1-4. 회원 탈퇴

회원 탈퇴가 완료되면 해당 회원은 즉시 로그아웃 처리되며 로그인 페이지로 이동한다.

탈퇴한 회원은 탈퇴 시점의 날짜가 deleted_at에 기록되고, 즉시 status가 DELETED로 변경된다.

탈퇴한 회원의 기본키인 user_id는 다른 테이블의 FK 참조 무결성을 유지하기 위해 삭제하지 않는다.

탈퇴한 회원의 회원 테이블 user row는 물리적으로 삭제하지 않고 유지한다.

탈퇴 처리 시 login_id, password, name, email_address 등 개인정보성 컬럼은 삭제하거나 식별할 수 없는 값으로 변경한다.

탈퇴 회원이 작성한 게시글, 댓글, 대댓글은 삭제하지 않고 유지한다.

탈퇴 회원이 작성한 게시글, 댓글, 대댓글의 작성자명은 화면에서 탈퇴한 유저로 표시한다.

탈퇴 회원이 작성한 게시글, 댓글, 대댓글이 익명으로 작성된 경우에는 탈퇴한 유저로 표시하는 것을 우선으로 한다.

탈퇴 회원의 개인 캘린더 및 개인 일정은 비활성화 처리되며 삭제 대기 상태로 전환된다.

탈퇴 시점에 해당 회원은 가입되어 있던 모든 그룹에서 탈퇴 처리된다.

단, 탈퇴 회원이 특정 그룹의 그룹장인 경우 해당 그룹에서 탈퇴 처리되기 전에 그룹장 권한을 다른 그룹원에게 자동 위임한다.

그룹장 권한은 탈퇴 회원을 제외하고 해당 그룹에 가장 먼저 가입한 그룹원에게 위임한다.

그룹장 권한 위임이 완료되면 탈퇴 회원은 해당 그룹에서 탈퇴 처리된다.

탈퇴 회원이 유일한 그룹원인 경우 해당 그룹은 비활성화 처리되며 삭제 대기 상태로 전환된다.

## 2. 알림 관리

### 2-1. 알림 식별

알림 테이블은 전용 테이블 아이디인 알림 id로 식별한다.

알림은 다음 정보를 유지해야 한다.

- 알림 id
- 알림 내용(comment_content)
- 알림 게시글(댓글이 달린 게시글의) id
- 알림 댓글(대댓글이 달린 댓글의) id
- 수신자 유저 id

댓글 알림의 경우 알림 게시글 id는 댓글이 달린 게시글을 의미하며, 알림 댓글 id는 null로 둔다.

대댓글 알림의 경우 알림 게시글 id는 해당 댓글이 속한 게시글을 의미하며, 알림 댓글 id는 대댓글이 달린 부모 댓글을 의미한다.

### 2-2. 알림 조회

회원은 알림 버튼을 클릭하여 자신에게 온 알림 목록을 팝업 형태로 조회할 수 있다.

회원은 다른 회원에게 온 알림을 조회할 수 없다.

### 2-3. 알림 읽음 처리 및 이동

회원이 알림을 클릭하면 해당 알림이 발생한 게시글 또는 댓글 위치로 이동한다.

댓글 알림은 해당 게시글 상세 화면으로 이동한다.

대댓글 알림은 대댓글이 달린 부모 댓글 위치로 이동한다.

알림은 회원이 자신에게 온 알림 목록을 팝업 형태로 조회했을 때 읽음 처리된다.

## 3. 게시글 관리

### 3-1. 게시글 작성

회원은 여러 개의 게시글을 작성할 수 있다.

게시글 하나는 한 명의 회원만 작성할 수 있다.

게시글은 글 id로 식별한다.

회원은 게시글 작성 시 익명 여부를 선택할 수 있다.

익명 게시글로 작성된 경우 게시글 목록과 상세 조회 화면에서 작성자 이름 대신 익명_숫자로 표시한다.

익명 게시글로 작성되더라도 시스템 내부에서는 작성자의 user_id를 유지한다.

게시글은 다음 정보를 유지해야 한다.

- 글 id
- 글 대주제(학과)
- 글 소주제(과목)
- 글 제목
- 글 내용
- 첨부파일
- 작성 일자
- 조회수
- 익명 여부

파일 업로드는 URL 목록 입력 방식이 아니라 사용자가 직접 파일을 업로드하는 방식으로 처리한다.

게시글 작성이 완료되면 게시판 첫 번째 페이지로 이동한다.

### 3-2. 게시글 수정 및 삭제

회원은 자신이 작성한 게시글을 수정하거나 삭제할 수 있다.

회원은 다른 회원이 작성한 게시글을 수정하거나 삭제할 수 없다.

게시글을 수정할 경우 수정 여부를 기록해야 한다.

게시글 삭제가 완료되면 게시판 첫 번째 페이지로 이동한다.

### 3-3. 게시글 조회

회원은 다른 회원이 작성한 게시글을 조회할 수 있다.

회원이 게시글 상세 조회 화면에 접근하면 해당 게시글의 조회수가 증가한다.

게시글 목록은 페이지 번호 기반 페이지네이션 방식을 사용한다.

게시글 목록의 기본 정렬은 작성일 기준 최신순으로 한다.

게시글 목록에서는 제목/내용 기준 검색어 필터, 작성자 필터, 주제 필터를 제공한다.

검색어 필터, 작성자 필터, 주제 필터는 한 번에 하나만 사용할 수 있다.

탈퇴한 유저의 게시글, 익명 유저의 게시글 등은 작성자 필터 결과에서 제외한다.

### 3-4. 게시글 추천

회원은 게시글에 추천을 할 수 있다.

회원은 하나의 게시글에 대해 추천을 한 번만 할 수 있다.

회원이 추천 버튼을 클릭하면 해당 게시글에 추천이 등록되고, 추천 버튼의 색상이 변경된다.

이미 추천한 게시글의 추천 버튼을 한 번 더 클릭하면 추천이 취소되고, 추천 버튼의 색상은 원래 상태로 돌아간다.

## 4. 댓글 관리

### 4-1. 댓글 작성

회원은 댓글을 여러 개 작성할 수 있다.

댓글 하나는 한 명의 회원만 작성할 수 있다.

게시글에는 댓글이 여러 개 달릴 수 있다.

댓글 하나는 하나의 게시글에만 작성될 수 있다.

댓글은 댓글 id로 식별한다.

회원은 댓글 작성 시 익명 여부를 선택할 수 있다.

익명 댓글로 작성된 경우 댓글 작성자 이름 대신 익명_숫자로 표시한다.

익명 댓글로 작성되더라도 시스템 내부에서는 작성자의 user_id를 유지한다.

댓글은 다음 정보를 유지해야 한다.

- 글 id
- 댓글 id
- 작성자
- 댓글 내용
- 작성 일자
- 익명 여부

### 4-2. 댓글 확인, 수정 및 삭제

회원은 자신이 작성한 댓글을 조회하거나 수정, 삭제할 수 있다.

회원은 다른 회원이 작성한 댓글을 조회할 수 있다.

회원은 다른 회원이 작성한 댓글을 수정하거나 삭제할 수 없다.

댓글을 수정할 경우 수정 여부를 기록해야 한다.

댓글을 수정하거나 삭제하면 해당 페이지 전체 화면을 갱신한다.

댓글 수정 또는 삭제로 인한 변경 내용과 함께, 화면 갱신 시점에 게시글 또는 다른 댓글에 변경 사항이 존재하는 경우 해당 변경 사항도 함께 반영하여 출력한다.

### 4-3. 대댓글 작성

회원은 대댓글을 여러 개 작성할 수 있다.

대댓글 하나는 한 명의 회원만 작성할 수 있다.

댓글에는 여러 개의 대댓글이 달릴 수 있으며, 개수 제한은 두지 않는다.

대댓글 하나는 하나의 댓글에만 작성될 수 있다.

대댓글에는 다시 대댓글을 작성할 수 없다.

회원은 대댓글 작성 시 익명 여부를 선택할 수 있다.

익명 대댓글로 작성된 경우 대댓글 작성자 이름 대신 익명_숫자로 표시한다.

익명 대댓글로 작성되더라도 시스템 내부에서는 작성자의 user_id를 유지한다.

대댓글은 다음 정보를 유지해야 한다.

- 댓글 id
- 부모 댓글
- 작성자
- 대댓글 내용
- 작성 일자
- 익명 여부

### 4-4. 대댓글 확인, 수정 및 삭제

회원은 자신이 작성한 대댓글을 조회하거나 수정, 삭제할 수 있다.

회원은 다른 회원이 작성한 대댓글을 조회할 수 있다.

회원은 다른 회원이 작성한 대댓글을 수정하거나 삭제할 수 없다.

대댓글을 수정할 경우 수정 여부를 기록해야 한다.

대댓글을 수정하거나 삭제하면 해당 페이지 전체 화면을 갱신한다.

대댓글 수정 또는 삭제로 인한 변경 내용과 함께, 화면 갱신 시점에 게시글 또는 다른 댓글에 변경 사항이 존재하는 경우 해당 변경 사항도 함께 반영하여 출력한다.

### 4-5. 익명 작성자 표시

익명으로 작성된 게시글, 댓글, 대댓글은 작성자 이름 대신 익명_숫자로 표시한다.

익명_숫자는 하나의 게시글 상세 화면을 기준으로 부여한다.

동일한 게시글 내에서 동일한 작성자는 항상 같은 익명_숫자로 표시한다.

서로 다른 게시글에서는 익명_숫자가 독립적으로 부여된다.

익명으로 작성되더라도 시스템 내부에서는 작성자의 user_id를 유지한다.

작성자 user_id는 수정, 삭제 권한 확인 및 관리 목적에 사용한다.

### 4-6. 탈퇴 작성자 표시

탈퇴한 회원이 작성한 게시글, 댓글, 대댓글은 삭제하지 않는다.

탈퇴한 회원이 작성한 게시글, 댓글, 대댓글의 작성자명은 화면에서 탈퇴한 유저로 표시한다.

탈퇴한 회원이 작성한 글이 익명으로 작성된 경우에는 작성자명을 탈퇴한 유저로 표시하는 것을 우선으로 한다.

탈퇴한 회원의 작성물은 기존 게시글 및 댓글 조회, 검색, 페이지네이션 대상에 포함된다.

탈퇴 작성자 여부는 회원의 status 또는 deleted_at을 기준으로 판단한다.

## 5. 개인 캘린더 관리

### 5-1. 개인 캘린더 식별

개인 캘린더는 User의 id(login_id가 아님을 유의)로 식별한다.

### 5-2. 개인 일정 등록

회원은 개인 캘린더에 여러 개의 일정을 등록할 수 있다.

회원이 개인 캘린더에 일정을 작성하면 일정에 대한 다음 정보를 유지해야 한다.

- 날짜
- 시작 시간
- 종료 시간
- 일정 종류
- 일정 제목
- 메모

개인 일정은 일정 id로 식별한다.

### 5-3. 개인 일정 조회, 수정 및 삭제

회원은 자신의 개인 일정을 달력 형태로 조회할 수 있다.

회원은 자신의 개인 일정을 수정하거나 삭제할 수 있다.

회원은 타인의 개인 일정을 조회하거나 수정, 삭제할 수 없다.

## 6. 그룹 관리

### 6-1. 그룹 가입

회원은 여러 그룹에 들어갈 수 있다.

하나의 그룹에는 여러 회원이 들어갈 수 있다.

### 6-2. 그룹 생성

회원은 여러 그룹을 생성할 수 있다.

그룹 하나는 하나의 회원만 만들 수 있다.

그룹은 그룹 id로 식별한다.

그룹은 다음 정보를 유지해야 한다.

- 그룹 id
- 그룹명
- 생성자
- 그룹 링크

그룹 생성자는 그룹 생성과 동시에 group_members에 자동 등록된다.

그룹 생성자의 역할은 LEADER로 설정한다.

### 6-3. 그룹 채팅

그룹 채팅은 구현하지 않는다.

---

## 7. 그룹 캘린더 관리

### 7-1. 그룹 캘린더 식별

그룹 캘린더는 그룹 id로 식별한다.

### 7-2. 그룹 일정 조회, 등록, 수정 및 삭제

그룹원은 그룹 캘린더에서 그룹 일정을 조회, 등록, 수정, 삭제할 수 있다.

모든 그룹원은 자신이 속한 그룹 캘린더의 그룹 일정을 자유롭게 조회, 등록, 수정, 삭제할 수 있다.

그룹원은 타 그룹 캘린더의 그룹 일정을 조회, 등록, 수정, 삭제할 수 없다.

그룹 캘린더는 다음 정보를 유지해야 한다.

- 일정 id
- 그룹 id
- 작성자
- 날짜
- 시작 시간
- 종료 시간
- 일정 종류
- 일정 제목
- 메모
