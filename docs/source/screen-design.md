## 4. 공통 화면 규칙

| 항목 | 규칙 |
|---|---|
| 인증 필요 화면 | `SC-04` 이후 주요 서비스 화면은 인증 필요로 본다. |
| 비인증 접근 | 인증 필요 화면 접근 시 로그인 화면으로 이동한다. |
| 로그아웃 | 로그아웃 시 서버에 저장된 사용자 세션을 무효화하고 로그인 화면으로 이동한다. |
| 성공 메시지 | 생성/수정/삭제 성공 시 사용자에게 처리 결과를 표시한다. |
| 실패 메시지 | API 오류의 공통 에러 응답 형식은 아직 결정 필요하다. 화면 설계에서는 오류 원인별 메시지 영역을 둔다. |
| 날짜/시간 입력 | 일정 화면은 시작 일시와 종료 일시를 입력한다. 종료 일시는 시작 일시보다 빠를 수 없다. |
| 권한 노출 | 수정/삭제 버튼은 가능한 경우 본인 또는 권한 있는 사용자에게만 노출한다. |
| 삭제 대기 데이터 | 탈퇴로 비활성화 또는 삭제 대기 상태가 된 게시글, 댓글, 개인 캘린더, 개인 일정, 그룹은 일반 사용 흐름에서 노출하지 않는다. |

### SC-05. 학습자료 상세 / 피드백

| 항목 | 내용 |
|---|---|
| 화면 목적 | 게시글 내용, 첨부파일, 댓글을 확인하고 댓글/대댓글/추천으로 피드백 작성 |
| 진입 경로 | 학습자료 목록에서 게시글 선택, 알림 클릭 후 대상 게시글 또는 댓글 위치 이동 |
| 주요 구성 | 제목, 작성자, 작성 일자, 조회수, 대주제/소주제, 본문, 첨부파일, 추천 버튼, 수정/삭제 버튼, 댓글 목록, 댓글 작성 영역 |
| 입력 필드 | 댓글 작성: `content`, `is_public`; 대댓글 작성: `content`, `is_public` |
| 버튼/액션 | 추천 등록, 추천 취소, 댓글 작성, 대댓글 작성, 게시글 수정, 게시글 삭제, 댓글 수정, 댓글 삭제 |
| 연동 API | `GET /api/posts/{post_id}`, 추천/추천 취소 API, `GET/POST /api/posts/{post_id}/comments`, `POST /api/comments/{comment_id}/replies`, `PATCH/DELETE /api/comments/{comment_id}`, `DELETE /api/posts/{post_id}` |
| 성공 처리 | 게시글 상세 표시. 추천 버튼 클릭 시 등록되고 색상이 변경되며, 이미 추천한 상태에서 다시 클릭하면 추천이 취소되고 색상이 원래 상태로 돌아간다. 댓글/대댓글 수정 또는 삭제 후 전체 화면을 갱신한다. 게시글 삭제 성공 시 게시판 첫 번째 페이지로 이동한다. |
| 검증/예외 | 게시글 없음, 권한 없음, 비공개 댓글 조회 권한 없음, 대댓글에 다시 대댓글 작성 시도 |
| 관련 요구사항 | 2-3, 3-2, 3-3, 3-4, 4-1, 4-2, 4-3, 4-4, 4-5 |
| 관련 유저 플로우 | UF-05, UF-07, UF-08 |

| 회원 | 아이디 중복, 이메일 중복, 필수값 누락, 로그인 실패, 탈퇴 계정 접근, 기존 정보와 동일한 값으로 수정 시도 |
