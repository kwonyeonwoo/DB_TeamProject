## 1. 서비스 목적

이 서비스는 학업 자료 공유와 학습 일정 관리를 위한 회원 기반 웹 서비스 백엔드다. 사용자는 게시판에서 학업 자료를 게시글과 첨부파일로 공유하고, 댓글과 대댓글로 피드백을 남기며, 개인 또는 그룹 단위 일정 관리를 수행한다. 관리자는 사용자 신고 내역을 조회하고 신고 처리 상태를 관리한다.

## 2. 주요 사용자

| 사용자 | 설명 |
|---|---|
| 비회원 | 로그인 또는 회원 가입 화면에 접근할 수 있다. 인증이 필요한 기능에는 접근할 수 없다. |
| 일반 사용자(USER) | 회원 가입으로 생성되는 기본 역할이다. 게시글, 댓글, 대댓글, 추천, 신고, 알림, 개인 일정, 그룹, 그룹 일정을 사용할 수 있다. |
| 관리자(ADMIN) | 신고 목록을 조회하고 신고 상태를 처리할 수 있다. ADMIN 권한은 회원 가입/API로 부여하지 않고 DB seed 또는 운영자 DB 변경으로만 부여한다. 일반 사용자 신고 생성 API는 USER 전용이다. |

## 3. 핵심 기능

| 기능 ID | 핵심 기능 | 요약 |
|---|---|---|
| AUTH-001 | 회원 가입 | 이름, 아이디, 비밀번호, 이메일로 USER 계정을 생성한다. |
| AUTH-002 | 로그인/로그아웃 | 서버 세션 기반 로그인과 세션 무효화 로그아웃을 제공한다. |
| USER-001/USER-002 | 내 정보 조회/수정 | 이름, 이메일, 비밀번호를 수정한다. 비밀번호 변경 시 현재 비밀번호를 검증한다. |
| USER-003 | 회원 탈퇴 | 회원 row는 유지하고 상태/탈퇴일을 기록한다. 개인정보성 컬럼은 탈퇴 시점에 즉시 변경하지 않고 `deleted_at`으로부터 6개월 후 NULL 또는 식별 불가 값으로 변경한다. |
| NOTI-001 | 알림 조회 | 본인 알림 목록을 팝업으로 조회하고 조회 시 읽음 처리한다. 자기 게시글/댓글에 작성한 댓글/대댓글 알림은 생성하지 않는다. |
| POST-001 | 게시글 조회/검색 | 최신순 게시글 목록, 단일 필터 검색, 상세 조회와 조회수 증가를 제공한다. |
| POST-002 | 게시글 작성/수정/삭제 | 게시글 작성, 본인 게시글 수정/삭제, 직접 파일 업로드를 처리한다. |
| POST-003 | 게시글 추천 | 게시글당 회원 1회 추천과 추천 취소를 제공한다. |
| COMMENT-001 | 댓글/대댓글 | 댓글과 1-depth 대댓글 작성, 수정, 삭제, 조회를 제공한다. |
| REPORT-001 | 사용자 신고 | USER가 게시글 또는 댓글을 정해진 사유로 신고한다. ADMIN은 이 기능의 권한 범위에 포함하지 않는다. |
| REPORT-002 | 관리자 신고 처리 | 관리자가 신고 목록을 조회하고 신고 상태를 처리 완료로 변경한다. |
| CAL-001 | 개인 일정 | 본인 개인 일정 조회, 등록, 수정, 삭제를 제공한다. |
| GROUP-001 | 그룹 생성/가입/조회 | 그룹 생성, 가입 코드 표시, 가입 코드 입력 가입, 그룹 상세 조회를 제공한다. |
| GCAL-001 | 그룹 일정 | 그룹원이 그룹 일정을 조회, 등록, 수정, 삭제한다. |

## 4. 제외 범위

| 제외 항목 | 정책 |
|---|---|
| 아이디 찾기 | 구현 범위에서 제외한다. |
| 비밀번호 찾기/재설정 | 구현 범위에서 제외한다. |
| ADMIN 권한 부여/회수 API | 구현 범위에서 제외한다. DB seed 또는 운영자 DB 변경으로만 처리한다. |
| 그룹 채팅 | 구현하지 않는다. |
| 복잡한 초대 링크/외부 공유 | 그룹 가입은 단순 코드 입력 방식만 사용한다. |
| 그룹 코드 만료/재발급 | 구현 범위에서 제외한다. |
| 파일 메타데이터 DB 저장 | 파일명, 원본 파일명, 파일 크기, MIME 타입, 확장자 등은 DB에 저장하지 않는다. |
| 파일 크기/확장자 정책 | 최소 구현 범위에서 별도 요구사항으로 두지 않는다. |
| 신고 처리 시 자동 삭제 | 신고 처리는 신고 상태만 변경하고 게시글/댓글 삭제를 자동 수행하지 않는다. |

## 5. 중요한 정책

### 공통 에러 응답

API 실패 응답은 `code`, `message`를 필수 필드로 사용한다. `details`는 입력값별 상세 오류가 필요한 경우에만 선택값으로 포함한다.

### 인증과 권한

인증은 서버 세션 기반이다. 로그인 성공 시 서버가 인증 세션을 생성하고, 로그아웃 시 세션을 무효화한다. 인증 필요 API는 유효한 세션이 있어야 호출할 수 있다.

회원 가입으로 생성되는 역할은 항상 `USER`다. `ADMIN`은 API로 부여하지 않는다.

### 회원 탈퇴

탈퇴 시 `users.status = DELETED`, `users.deleted_at = now()`로 처리한다. 회원 row와 작성물은 유지한다. 탈퇴 회원 작성물은 화면에서 `탈퇴한 유저`로 표시하며 익명 표시보다 우선한다.

탈퇴 처리 시점에는 개인정보성 컬럼(`login_id`, `password`, `name`, `email_address`)을 즉시 변경하지 않는다. `deleted_at`으로부터 6개월이 지난 탈퇴 회원은 개인정보 삭제 대상으로 처리하며, 해당 컬럼은 NULL 값으로 변경한다. NULL 값이 들어갈 수 없는 속성은 식별할 수 없는 값으로 변경한다.

### 익명 표시

익명 작성물은 게시글 상세 화면 기준으로 `익명_숫자`를 부여한다. 동일 게시글 안에서 동일 작성자는 항상 같은 익명 번호를 사용한다.

### 파일 업로드

게시글 첨부파일은 사용자가 직접 업로드한다. 실제 파일은 서버 로컬 경로 `/uploads/posts/{post_id}/...`에 저장하고, DB에는 `file_url`만 저장한다. 게시글 수정 시 새 파일이 업로드되면 기존 첨부파일 목록을 전체 교체하고, 새 파일이 없으면 기존 목록을 유지한다.

### 신고 처리

신고 대상은 게시글 또는 댓글/대댓글이다. 동일 회원은 동일 대상에 한 번만 신고할 수 있다. 신고 생성 시 `PENDING` 상태로 저장하고, 관리자가 처리하면 `PROCESSED`, `processed_by`, `processed_at`만 변경한다.

### 그룹 가입

그룹 생성 시 `group_code`를 생성해 화면에 보여준다. 화면에서 `group_link`라고 표현하는 값은 별도 URL이 아니라 `group_code`와 같은 값이다. 가입자는 코드를 입력해 그룹에 가입한다.

### 알림 생성

댓글 작성자가 게시글 작성자와 다른 회원이면 게시글 작성자에게 댓글 알림을 생성한다. 대댓글 작성자가 부모 댓글 작성자와 다른 회원이면 부모 댓글 작성자에게 대댓글 알림을 생성한다. 작성자와 알림 수신자가 같은 경우에는 알림을 생성하지 않는다.

## 6. Assumptions

- 비밀번호 저장 방식, 세션 저장소, 파일명 충돌 방지 방식, 페이지 기본 크기 같은 구현 세부값은 source 문서에 고정되어 있지 않다. 구현 단계에서는 프레임워크의 안전한 기본값과 로컬 규칙을 사용하되 API 계약을 바꾸지 않는다.
- `report.target_id`는 다형 참조이므로 DB 단일 FK로 강제하지 않고 서비스 로직에서 대상 존재 여부를 검증한다.
- 6개월 경과 탈퇴 회원의 개인정보성 컬럼 처리 실행 방식은 구현 세부사항이며, source의 6개월 후 처리 정책과 API 계약을 바꾸지 않는다.
