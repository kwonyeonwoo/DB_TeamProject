# DB Schema Contract

기준 문서: `docs/source/logical-schema.md`, `docs/source/physical-schema.md`, `docs/source/erd.md`, `docs/source/dbml.md`

검증 상태: PASS - source 문서 기준 DB 계약 충돌 없음

작성 기준:

- SQL 표기는 source 물리 스키마의 일반 SQL 표현을 따른다.
- MySQL 적용 시 `GENERATED BY DEFAULT AS IDENTITY`는 `AUTO_INCREMENT`, `CLOB`은 `TEXT`로 치환할 수 있다.
- 논리/물리/ERD의 테이블/컬럼/제약 검증 결과는 PASS다.
- 회원 탈퇴 후 개인정보성 컬럼은 탈퇴 시점에 즉시 변경하지 않고, `deleted_at`으로부터 6개월 후 NULL 또는 식별 불가 값으로 변경한다.

## 1. Tables

### users

| Column | Type | Nullable | Key/Constraint | Default | Description |
|---|---|---:|---|---|---|
| `id` | INTEGER identity | no | PK | - | 회원 식별자 |
| `login_id` | VARCHAR(50) | yes | UNIQUE | - | 로그인 아이디. 탈퇴 후 NULL 가능 |
| `password` | VARCHAR(255) | yes | - | - | 비밀번호. 탈퇴 후 NULL 또는 식별 불가 값 가능 |
| `name` | VARCHAR(50) | yes | - | - | 이름. 탈퇴 후 NULL 또는 식별 불가 값 가능 |
| `email_address` | VARCHAR(255) | yes | UNIQUE | - | 이메일. 탈퇴 후 NULL 가능 |
| `created_at` | TIMESTAMP | no | - | CURRENT_TIMESTAMP | 가입 일시 |
| `deleted_at` | TIMESTAMP | yes | - | - | 회원 탈퇴 일시 |
| `status` | VARCHAR(20) | no | CHECK `ACTIVE`, `DELETED` | `ACTIVE` | 회원 상태 |
| `role` | VARCHAR(20) | no | CHECK `USER`, `ADMIN` | `USER` | 사용자 역할 |

Additional checks:

- `status = DELETED OR login_id IS NOT NULL`
- `status = DELETED OR password IS NOT NULL`
- `status = DELETED OR name IS NOT NULL`
- `status = DELETED OR email_address IS NOT NULL`

Lifecycle note:

- `login_id`, `password`, `name`, `email_address`는 탈퇴 후 삭제/비식별화를 지원하기 위해 nullable이다.
- 탈퇴 처리 시점에는 개인정보성 컬럼을 즉시 변경하지 않는다.
- `deleted_at`으로부터 6개월이 지난 탈퇴 회원은 개인정보 삭제 대상으로 처리하며, `login_id`, `password`, `name`, `email_address`는 NULL 값으로 변경한다. NULL 값이 들어갈 수 없는 속성은 식별할 수 없는 값으로 변경한다.

Indexes:

- `idx_users_status(status)`
- `idx_users_deleted_at(deleted_at)`

### post

| Column | Type | Nullable | Key/Constraint | Default | Description |
|---|---|---:|---|---|---|
| `id` | INTEGER identity | no | PK | - | 게시글 식별자 |
| `user_id` | INTEGER | no | FK -> `users.id` | - | 게시글 작성자 |
| `title` | VARCHAR(255) | no | - | - | 제목 |
| `content` | CLOB | yes | - | - | 본문 |
| `created_at` | TIMESTAMP | no | - | CURRENT_TIMESTAMP | 작성 일시 |
| `updated_at` | TIMESTAMP | yes | - | - | 수정 일시 |
| `deleted_at` | TIMESTAMP | yes | - | - | 삭제 일시 |
| `status` | VARCHAR(20) | no | CHECK `ACTIVE`, `DELETED` | `ACTIVE` | 게시글 상태 |
| `view_count` | INTEGER | no | CHECK `>= 0` | 0 | 조회수 |
| `main_category` | VARCHAR(100) | no | - | - | 대주제 |
| `sub_category` | VARCHAR(100) | no | - | - | 소주제 |
| `is_anonymous` | BOOLEAN | no | CHECK boolean | FALSE | 익명 여부 |

Foreign keys:

- `post.user_id -> users.id ON DELETE NO ACTION ON UPDATE CASCADE`

Indexes:

- `idx_post_user_id(user_id)`
- `idx_post_status_created_at(status, created_at)`
- `idx_post_category(main_category, sub_category)`
- `idx_post_created_at(created_at)`
- `idx_post_author_filter(user_id, is_anonymous, status)`

### report

| Column | Type | Nullable | Key/Constraint | Default | Description |
|---|---|---:|---|---|---|
| `id` | INTEGER identity | no | PK | - | 신고 식별자 |
| `reporter_id` | INTEGER | no | FK -> `users.id`, UNIQUE(`reporter_id`, `target_type`, `target_id`) | - | 신고한 회원 |
| `target_type` | VARCHAR(20) | no | CHECK `POST`, `COMMENT` | - | 신고 대상 유형 |
| `target_id` | INTEGER | no | UNIQUE(`reporter_id`, `target_type`, `target_id`) | - | 신고 대상 id |
| `reason_type` | INTEGER | no | CHECK 1, 2, 3, 4 | - | 신고 사유 |
| `created_at` | TIMESTAMP | no | - | CURRENT_TIMESTAMP | 신고 시각 |
| `status` | VARCHAR(20) | no | CHECK `PENDING`, `PROCESSED` | `PENDING` | 신고 처리 상태 |
| `processed_by` | INTEGER | yes | FK -> `users.id` | - | 처리한 관리자 |
| `processed_at` | TIMESTAMP | yes | - | - | 처리 시각 |

Foreign keys:

- `report.reporter_id -> users.id ON DELETE NO ACTION ON UPDATE CASCADE`
- `report.processed_by -> users.id ON DELETE NO ACTION ON UPDATE CASCADE`

Indexes:

- unique `report(reporter_id, target_type, target_id)`
- `idx_report_reporter_id(reporter_id)`
- `idx_report_target(target_type, target_id)`
- `idx_report_created_at(created_at)`
- `idx_report_reason_type(reason_type)`
- `idx_report_status(status)`
- `idx_report_processed_by(processed_by)`

Notes:

- `target_id`는 `target_type`에 따라 `post.id` 또는 `comments.id`를 의미한다.
- 다형 대상 존재 여부는 서비스 로직 또는 트리거로 검증한다.
- 신고 처리 API는 `status`, `processed_by`, `processed_at`만 변경한다.

## 3. Cascade Rule Summary

| Parent | Child | Delete | Update |
|---|---|---|---|
| `users` | `post`, `comments`, `likes`, `report`, `groups`, `group_members`, `schedules`, `notification` | NO ACTION for user references | CASCADE |
| `post` | `likes`, `comments`, `file`, `notification` | CASCADE | CASCADE |
| `comments` | `comments.parent_comment`, `notification.commented_id` | CASCADE | CASCADE |
| `groups` | `group_members`, `schedules` | CASCADE | CASCADE |

Business deletion is normally soft deletion via `status` and `deleted_at` where those fields exist.

## 4. Assumptions

- DBMS-specific syntax changes must preserve all columns, constraints, defaults, and indexes.
- `report.target_id` existence validation is implemented in service logic unless the chosen DB layer supplies a safe trigger abstraction.
- 6개월 경과 탈퇴 회원의 개인정보성 컬럼 처리 실행 방식은 구현 세부사항이며, 현재 nullable 컬럼 구성으로 source의 6개월 후 처리 정책을 지원한다.
